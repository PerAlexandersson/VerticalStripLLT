# Retain endpoint data in component checks

Unmarked HRV partitions do not record which fibres meet the attachment
vertices. Checking only those partitions can miss a false gluing argument.

The resumed endpoint diagnostic records the two endpoint fibre sizes,
their coincidence flag and the remaining partition. If the external flip
diagnostics become maintained Rust APIs, retain this optional marked profile
and tests with coincident and distinct endpoint fibres. Keep the existing
whole-component BFS check alongside it: a valuation equality alone does not
certify component reassembly. This is a proposal, not an API change.
